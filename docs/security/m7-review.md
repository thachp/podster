## Verdict

**The design holds where it matters most.** No path was found by which a task command reaches the provider key, Runner's Agent Auth key, the repository token, Runner's policy or state, or another task's folder. The provider key exists only in Runner's process and is added by the transport to a fixed URL. Claude Code runs in its own container with no host mount and only a per-run token. Task commands run in a second container with only the task's folder mounted, no network unless the room lists hosts, and then only HTTPS to those exact names through a proxy. Git runs on the host with its configuration and folder outside the container, and the token reaches it only on a pipe. Nothing Podster sends can switch unattended runs on.

**What is short is evidence, and one output channel.** Four findings are rated blocking for the gate:

- the subprocess escape suite, R-08 and R-30's "actual subprocess tests", has never run, and the one real run predates the egress proxy, toolchains and the Linux path (F-1);
- Runner pushes the task branch and opens its pull request before the owner's review, in every room, `outputs: "hold"` included, and doesn't read whether the repository is public (F-2, S-34);
- the "trust statement" an unattended room must accept doesn't exist as text; it is a bare `true` in `policy.json`, and the README's example sets it (F-3);
- Runner already runs tasks on Linux and WSL2 once its start check passes, but S-47's end-to-end rerun on a Linux host hasn't happened, and neither has step 16's WSL2 run (F-4).

**Decision 29's default should stay ask-first** until F-1, F-3 and F-5 are closed. Conditions 1 to 4 hold as built; condition 5 holds in part ([below](#decision-29s-five-conditions)).
